## Triage Walkthrough: "Discovery activity executed"

### Alert details

| Field | Value |
|---|---|
| Agent | win-10 (001) |
| Rule | Discovery activity executed |
| Channel | Microsoft-Windows-Sysmon/Operational |
| Process | `net1.exe` (original file name) |
| Parent command line | `net user` |
| Parent image | `C:\Windows\SysWOW64\net.exe` |
| User | `NT AUTHORITY\SYSTEM` |

![Event details](../screenshots/10-sysmon-event-details.png)

### Investigation steps

1. **What happened?** `net user` enumerates local accounts, a common discovery technique.
2. **Who ran it?** `SYSTEM`, which is not an interactive user.
3. **What is the process chain?** Check the grandparent (`parentProcessGuid` → find the parent's own event). If it traces back to the Wazuh agent (`wazuh-agent.exe` / `ossec-agent`), it's SCA or agent activity.
4. **Timing:** Alerts clustered right after the SCA scan ran (SCA alerts at ~14:41, Sysmon discovery alerts at ~14:54). [Confirm in your timeline.]
5. **Verdict:** [Likely benign, generated by agent/system checks. Confirm via process tree.]

### Takeaway

Detection rules can fire on legitimate tooling. Always confirm the process lineage before escalating, and tune noisy rules rather than disabling them blindly.
